## Operating gotchas (earned the hard way — do not relearn)
- **Never clear `.cache/anvil-sandbox` while a test run is in flight.** It is the live sandbox root now, so clearing it deletes running tests' working dirs *and* their stdout/stderr capture files — surfacing as a `book_examples` failure with **empty** output. Clear before or after, never during. A failure with no captured output at all ⇒ suspect the harness's scratch before the code.
- **Never mass-rewrite strings across docs whose *subject* is that string.** A blanket `/tmp` sweep once turned decision `0030`'s own `reverify` into the meaningless `ls -d anvil-*`. Always allow-list the policy/history documents first.
- **`git checkout -- <file>` during a negative-control sweep discards unrelated edits to that file.** It silently cost a README citation that a commit message then claimed; `CHANGES.md` is append-only so the fix is to make the claim true in the next leaf, never to rewrite it. Re-read `git diff --cached --name-only` before writing commit prose. **Same class:** never baseline a metric against a file you have already edited — the README-policy tree was first registered with `1773 lines / 122,920 B`, measured *after* this session's own 2-line README edit (true HEAD: `1771 / 122,767`). Baseline from `git show HEAD:<file>`, not the worktree. **Same class, deleting docs (`0036`/`.2`):** (i) grep the **doctrine checks** for the file first — they encode invisible content requirements (`README.md` was a declared `ENUMERATION-PARITY` pair-4 site, so cutting one `--steer` bullet inside a 1141-line deletion would have failed the hook; the fix is to **drop the site**, decision `0033` R1, never to re-add a list "to keep the gate green" — that list grows one line per future category, which is how the file reached 1771); (ii) grep **`src/`** too — a doc comment can name where a fact is *cited* (two `tool_matrix.rs` comments said "cited in `README.md`"), and no docs-side check sees that lie; (iii) to prove nothing was lost, sweep **every** token in the deleted range (879 here), not a hand-picked phrase list — a working sweep's residue is made only of **composites of covered parts**, and an orphaned fact stands out in a set of 32 where it would hide in 879; (iv) a **line cap and a byte cap are not redundant** — the survivors were `10,297 B / 141 lines`, so the projected file was *over* the byte cap while at 74 % of the line cap (prose density: 118 B/line for a numbered list vs 57 for a path list). Trim to the cap; never raise the cap to fit the trim.
- **Under mutual exclusion with a fixed pass order, probability is PRIORITY, not intensity.** All nine `*_emit_prob` at `1.0` ⇒ `function_emit` (2nd) claims every admissible gate and 5 later surfaces emit ZERO — measured: `--profile structured-emission-max` sets 4 surfaces and emits **1**. Max *coverage* and max *diversity* are opposed; ANVIL wants diversity ⇒ calibrate by **max-min** (`0.25` maximises the least-represented surface). A tenth surface joins at the shared intermediate value, never at `1.0`. Decision `0032`.
- **Auditing a defect class — three rules, all earned by `SHADOW-ENUMERATION-SWEEP`.** **(0) Never write "currently correct" without MEASURING it, and treat a COUNT beside a list as a shadow OF that list.** The tree opened on *"nothing here is a live bug; correctness merely rests on diligence."* Measured, **five** omissions had already happened: the MCP `instructions` named 3 adapters and `validate`'s description 4 (vs 5 registered); `book/src/architecture.md` + the `doctrine-enforcement` KM card + `CODEBASE_ANALYSIS.md` each named 4 doctrines (vs 6). All five were **prose** — the copy nobody greps when adding an entry. A stale KM card is worst: it is read *instead of* re-deriving, so it misinforms rather than omits. Redundant counts (`"Live registry (6)"`, `"is four doctrines"`) are R1-by-**deletion**, never "gate the count too" — that keeps the shadow alive and spends a mechanism on it forever. **(1) Rank by what one omission CORRUPTS, never by list length, and check the CONSUMER's polarity before ranking the producer.** `merge_coverage` (149 entries) looked worst until measured: all merges monotone (`135 |=` + `13 extend` + `1 max`) ⇒ under-report only, and 134/149 fields are read as `if !saw_x` ⇒ a forgotten merge yields a *spurious* gap ⇒ the gate **bails loudly**. Silent surface = 15, fail-safe. The real S3 was a 15-term `||` chain: omit a gate from `fail_on_coverage_gap` and `:1490`'s `bail!` is disarmed ⇒ a gate that **cannot fail**, banked as `0030` evidence. **(2) Search from the AUTHORITATIVE SET, never from the shadow you found first.** `.2` swept for the *shape* of the known instance (a JSON `enum` array) ⇒ 4 MCP adapter-id copies; `.6` swept for the *content* (any line naming ≥ 2 registry ids) ⇒ **7**, and the 3 extra were the only ones that had **already rotted** (the server `instructions` named 3 adapters, `validate`'s description 4, vs a registry of 5). A shape-keyed search silently narrows the class to *structured* copies; prose passes all three tests too, and under decision `0017` a tool description **is** the contract. Corollary: a guard that lists the known sites is one more copy of the set — walk the real output instead. Decision `0033` (also: a list is a shadow only if derivable **∧ growth-coupled ∧** silent — the middle test is what keeps the two load-bearing allow-lists hand-written). **Rule (2) again, 2nd lane (`0034`):** before claiming *"all X funnel through one place"*, search the **effect** (the write/record/insert — here `knob_rolls.record(`, 8 sites/2 files) not the funnel (`roll_knob(`, 1 file, false premise) — a 2nd funnel is DEFINED by producing the same effect a different way. And a proof sampling ONE member of a set cannot detect the set is **partitioned** (`.2a` proved steering on a `cone.rs` knob; all 7 `hierarchy.rs` knobs were unsteered for 2 months).
- **The fixture agrees with you; the tool does not.** Three independent instances now (`DIFFERENTIAL-SIMULATION.3b.2` two-space `input  logic`; `PHASE-7 .2c.2b.1` `rem_euclid` vs `%`; `EVIDENCE-BANK-DURABILITY.5` a deriver reporting *2907 gaps* for an empty array). Run a new tool against **real** output before trusting it — a hand-made fixture is shaped by the same assumption as the parser.
- **Never parse a FORMATTER's output for a semantic set.** `ENUMERATION-PARITY`'s steering extractor read **7 of 8** categories for its whole life: `grep -oE '=> "[a-z]+"'` assumed a one-line match arm and **`rustfmt` blocked the one arm whose pattern got long enough to wrap**, so `=>` and the string landed on different lines. Measured across all six extractors: the five parsing structure a *tool* controls (bash array, Markdown column, directory listing, link syntax) are exact; the only one parsing `rustfmt` output was the only one wrong — and it degrades exactly when a category **grows**. Three corollaries: **(a) a count floor catches "matched nothing", not "matched most"** (floor 6, extractor 7) — when an extraction can be off by one, the floor must be the real count, which is safe because a floor is **shrink-coupled, not growth-coupled** and so fails `0033`'s three-part shadow test; **(b) a one-directional `covers_set` turns a missing extraction into a SILENT EXEMPTION** (an id never extracted is checked nowhere), so bias extractors toward over-matching and strip only provable noise — over-matching cries wolf and gets noticed, under-matching is invisible; **(c) measure whether the guarded thing actually drifted, separately from whether the guard works** — all four doc sites did name `datapath`, so this was a latent hole, not a live inconsistency, and saying otherwise would have been as wrong as missing it. **`grep -E` uses ERE: the interval is `{0,1}`, NOT `\{0,1\}`.** `sed` is BRE and wants the backslashes. This repo's scripts mix both dialects; the escaped form inside `grep -E` matches a literal brace and silently never fires. An extractor must die on a missing field, never fall through to something plausible.
- **A doctrine check must classify, never guess.** `EVIDENCE-CITATIONS` requires every `anvil-<name>` token to be in one of three buckets and fails closed on an unknown one; a heuristic would either miss a real uncited bank or cry wolf on prose, and a gate that cries wolf gets deleted. Its grandfathered list is pinned by count+SHA **because its membership is a historical fact** — unpinned, "just grandfather it" bypasses the doctrine in one line.
- **`cmd | tail` DESTROYS `cmd`'s exit status** (bash returns the last stage's). Bit twice on `2026-07-30`: `cargo test 2>&1 | tail -30` "passed" while proving nothing, and `git commit -F brief && truncate -s 0 brief` ran the `truncate` after the hook REJECTED the commit — emptying the message file. Redirect to a log and echo `$?` on its own line; never chain `&&` cleanup off a piped command.
- **Run `scripts/check_doctrines.sh` AFTER `git add`.** `git grep`/`git ls-files` see tracked content only, so a new file's contents are invisible to every structural check until staged. Three self-catches in two days were all this blind spot.
- **Anchor a path-prefix rewrite to a path start.** The same sweep, applied unanchored, also fired *inside* `target/tmp/…` (Cargo's `CARGO_TARGET_TMPDIR`, on-volume) and minted 10 paths to a directory that never existed. A wrong path that looks plausible survives review. And a gate built from the sweep's own search string shares its blind spot — write the check from the property ("a boot-volume path is absolute"), not the string.
- `verilator -Wall` on a fixed-filename dump always fails `DECLFILENAME` — pass `-Wno-DECLFILENAME`; it is a filename artifact, not a defect.
